# アカウントと任意クラウドバックアップ (2026-10-19)

要望「Cloudflare D1使ったログイン機能ほしいかも」への実装。**ローカルファーストを維持**し、アカウントは完全に任意。

## 方針

| 項目 | 内容 |
|---|---|
| アカウント無し | 全機能が動く。ネットワーク通信ゼロ。記録は端末内のみ |
| アカウント有り | 進行データを**任意で**Cloudflare D1にバックアップし、別端末で復元できる |
| 送信するもの | メールアドレスと、ブラウザで導出したパスワード検証子のみ |
| 送信しないもの | 走行ログ・刺激ログ・生データ・Index。バックアップは本人がボタンを押した時だけ |

## 構成

- **Worker**（`worker/index.js`）: 認証APIとプロフィール保管。`/api/*` 以外は静的アセットを返す
- **D1**（`focus-drive-users`, id `7b1c9678-c1fb-4646-bd2b-c9f1755352fe`）: `users` / `sessions` / `profiles`
- **クライアント**（`src/persistence/account.ts`）: 鍵導出とAPI呼び出し
- **UI**: 設定モーダル内の「ACCOUNT・任意」パネル

### API

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/auth/me` | 現在のサインイン状態（未サインインでも200 + `{user:null}`。毎回の401でコンソールが汚れるのを避けるため） |
| POST | `/api/auth/register` | 新規登録＋セッションCookie |
| POST | `/api/auth/login` | サインイン |
| POST | `/api/auth/logout` | サインアウト |
| GET | `/api/profile` | クラウド上のプロフィール取得 |
| PUT | `/api/profile` | プロフィールを保存 |

## パスワードの扱い（重要）

**PBKDF2はブラウザ側で実行する。** サーバーでは実行しない。

理由: Cloudflare Workersの無料枠はCPU時間がリクエストあたり約10ms。PBKDF2-SHA256 210,000回はこの環境で**111ms**かかり、実測でも500エラーになった（2,000回に落とすと成功）。サーバー側で十分な強度のKDFを回すと、この構成では動かない。

そこで:

1. ブラウザで `verifier = PBKDF2-SHA256(password, salt=SHA-256("focus-drive:v1:"+email), 600,000回)` を計算
2. サーバーは `verifier` を受け取り、**ユーザーごとのランダムsalt**と共に1回のSHA-256で保存
3. ログイン時もブラウザが同じ `verifier` を導出して送る

saltをメールのハッシュにしてあるので、事前問い合わせなしで導出でき、「このメールは登録済みか」をAPIで探ることもできない。DBが漏れても、各推測には高コストなKDFが必要（保存されているのはverifierそのもの）。

その他の対策:
- セッションは256bit乱数。DBには**SHA-256ハッシュのみ**保存
- Cookieは `HttpOnly; Secure; SameSite=Lax`、30日
- 8回失敗で15分ロック
- タイミング差が出ないよう定数時間比較
- ボディ64KB上限、プロフィール512KB上限

**限界（正直に）:** パスワード強度の検証はブラウザ側のみ（サーバーはverifierしか見ないため）。サーバー側の追加ハッシュは1回のSHA-256で、高コストKDFの代わりにはならない。パスワードリセット・メール確認・二要素認証・レート制限（IP単位）は未実装。

## Service Workerとの関係

SWは **`/api/` を一切キャッシュしない**。当初これをキャッシュしてしまい、サインアウト後も `/api/auth/me` が古い「サインイン済み」応答を返す不具合になった（`scripts/build-sw.mjs` で除外し、回帰テストを追加）。

## 検証

### ユニット（`tests/unit/account-api.test.ts`）
実SQLite（`node:sqlite`）でD1を模擬し、**実際のWorkerハンドラ**を実行:

- 登録・識別・サインアウト、Cookie属性、生パスワードを保存しないこと
- 重複登録409、不正メール400、不正な鍵400
- 誤パスワード401 → 8回で429ロック
- 存在しないメールでも401（列挙防止）
- プロフィールのバックアップ／復元、**他人のバックアップは見えない**
- 512KB超は413、非APIパスは静的アセットへ
- WorkerがNode専用グローバル（`Buffer`/`process`/`require`）を使っていないこと — これを入れる前は本番で500になった
- 同じメール・パスワードから同じverifierが出ること

### 本番（`pnpm verify:account`）
デプロイ済みURLに対する実ブラウザ検証:

| 手順 | 結果 |
|---|---|
| パネル表示・初期状態はサインアウト | PASS |
| 短いパスワードを拒否（日本語メッセージ） | PASS |
| 新規登録 → サインイン表示 | PASS |
| クラウドへ保存 | PASS |
| リロード後もセッション維持・パネルがサインイン表示 | PASS |
| サインアウト | PASS |
| ページエラー | 0 |

curlでのAPI検証も実施: 201/200/409/401/413、静的配信・SPAフォールバック・`sw.js` は200のまま。

## デプロイ

```bash
pnpm run deploy:workers     # アカウントAPIを含めてビルド・デプロイ
pnpm verify:account        # 本番のアカウントUIを実ブラウザ検証
```

D1のIDは `cloudflare.config.ts` と `scripts/build-workers-output.mjs` にあり、`FOCUS_DRIVE_D1_ID` で上書きできる。
