# ゲームフィール改善 第1弾 (2026-10-19)

プレイヤー要望への対応記録。数値はボット計測およびこの環境（AMD RX 6400 / Chrome）での実測で、人間の体感評価ではない。

## 1. ガイドが1個も集まらない問題（修正）

### 原因

ゲーム既定の「高負荷チャレンジ」がガイド条件を厳しくしすぎていた。ロック中は以下を**同時に**満たす必要があった。

- 直近30秒の道路内割合 ≥ 88%
- 直近30秒のHIT率 ≥ 80%
- 直近のイベント成功率 ≥ 75%
- 上記を保ったまま2.6秒以上ロックを維持

人間には実質不可能で、2回プレイして0個は仕様どおりの結果だった。

### 変更

| 項目 | 旧 | 新 |
|---|---|---|
| 最初のアプローチ | 12.0s | **7.0s** |
| アプローチ時間 | 2.0s | 1.8s |
| ロック維持時間 | 3.5s | **2.6s** |
| クールダウン | 6.0s | 4.5s |
| 必要道路内割合（挑戦時） | 88% | **80%** |
| 必要道路内割合（標準） | 80% | 72% |
| 必要イベント成功率（挑戦時） | 75% | **55%** |
| ロック判定の幅 | 3.2m | 3.6m |
| ロック減少速度 | 0.25/s | 0.18/s |
| 必要ターゲット試行 | 8 | 6 |
| 必要target/non-target | 3 / 3 | 2 / 2 |

さらに**止まっている理由をHUDに表示**するようにした（`GuideSnapshot.blockedBy`）。表示は「ラインを維持」「サインに反応」「イベントを通過」「リングへ寄る」「車線へ戻る」。

### 実測

現実的な腕前のボット（狙い誤差σ=1.15m、Target的中率85%、イベント注視85%）で180秒ミッション：

| 指標 | 変更前 | 変更後 |
|---|---|---|
| ガイド捕獲数 | **0** | **6** |
| 道路内 | — | 0.961 |
| イベント成功率 | — | 0.627 |
| Target精度 | — | 0.854 |

ロック可能時間の内訳：`ANSWER_THE_SIGNS` 46%、`CLEAR_THE_EVENTS` 35%、`LOCKING` 16%、`OFF_LINE` 4%。残る律速は「直近30秒の標識成績」と「イベント成功率」で、これは二重課題の維持として意図どおり。

回帰テスト：`tests/unit/game-feel.test.ts`。片方の課題だけ成功するボットは依然としてガイドを取れないことも検証。

## 2. 刺激のテンポ（高負荷チャレンジのみ）

Classicの公開仕様（400ms表示、2/2.5/3秒、72試行）は**一切変更していない**。

- **提示間隔を短縮＋ランダム化**：1400〜2600msで毎回抽選（旧：2000/2500/3000msの固定セット）。180秒で約90試行。
- **表示時間をレベルに応じて適応**：Signレベル1で520ms → レベル54で**300ms**。消えるまでの時間だけが縮み、反応期限（responseWindow）は別管理のまま。
- 標準OTC・Classic・Arcadeは従来のケイデンスを維持。

## 3. 高速域のステアリング

`steeringForce` の高負荷チャレンジ側ゲインを強化：`18 + max(0, speed-40) × 0.42`（旧 `18 + max(0, speed-60) × 0.25`）。

315km/h時の横方向権限は約9.5m/sで、コース最大傾斜が要求する約4.9m/sの**約1.9倍**。Classicと標準プロファイルは従来の固定値18のまま（比較計測を壊さないため）。

## 4. スピードメーター（ATギア付き）

HUD右下に計器クラスタを追加。

- **8速ATギア表示**（速度から算出。Nは停止時）。境界のちらつきを抑えるヒステリシス付き。
- **タコメーター風アーク**：現在ギア帯の中での回転数を0〜1で表示。高回転でレッドライン色。
- デジタルkm/h（等幅数字）。
- 純粋な表示のみで、シミュレーションには一切影響しない。

## 5. 速度演出

- 175km/h超で放射状の速度線と周辺ビネット、265km/h超でさらに強く。
- 既存のPower Zone加速時のサージ演出と併用。
- `prefers-reduced-motion` と設定「演出を控えめに」で無効化。

## 6. ナイトドライブ

設定に「ナイトドライブ」を追加。ONにすると**どのワールドでも走行中が夜の照明・空・フォグ**になる（ワールドの地形はそのまま）。空の環境マップは昼夜で別キャッシュ。

## 7. 文字サイズ

6〜10pxだったラベル類を機械的に引き上げた（本文系 +3px、上限14px。レスポンシブ指定は +2px、上限13px）。107個の通常ルールと7個のメディアクエリを更新。

副作用として390px幅でヘッダー（LOCAL SAVE / コイン / アバター）が37px溢れたため、560px以下ではヘッダー中央のタグラインとLOCAL SAVE表示を省き、余白を詰めた。

## 追記（第2弾・同日）

### 放置すると道路から外れる件（第2版・設計書準拠に修正）

**最初の修正は設計書違反でした。** 設計書 §3.4 は明記しています。

> セルフセンタリング: 操舵を戻すと無理なく走行姿勢が整う。**勝手に道路中央へ完全自動追従してはいけない。**

初版では曲率フィードフォワードを入れて「放置すると道路中央を走る」状態にしていました。これではナビゲーション課題そのものが消えます。現在は3段階に分けています。

| 設定 | 挙動 | 既定 |
|---|---|---|
| **中央へ戻る（center）** | 操舵を離すと姿勢が整う。カーブは自分で曲がる | **これ** |
| 道路に自動追従（full） | 放置でも中央を走る（設計書では非推奨。かんたん用） | |
| 補助なし（manual） | 原型モデルそのまま | |
| Classic | 常に manual（再構成した物理を変えない） | 固定 |

### 「常時修正がうざい」の本当の原因（コース形状）

物理ではなく**コースと評価幅の比率**でした。

| | 旧 | 新 |
|---|---|---|
| 道路中心の蛇行振幅 | ±7.2m | **±4.0m** |
| 評価幅（Lv20 / 高Lv） | ±2.86m / ±1.75m | 同左 |

振幅が評価幅の**2.5倍**あり、「±2.9mの廊下」を「±7.2mで蛇行する線」に沿って走る構造だったため、常時の微修正が必要でした。振幅を±4.0mに下げ、比率を約1.4倍にしました。カーブは残るので課題は成立し、修正は数秒に1回程度になります。

コース形状はマニフェストで「game substitution/inferred」と明記している推定値なので、公開値の変更ではありません。ただし**Classicの走路も同じ形状になる**点は許容してください（Classicの公開値は秒数・提示時間・間隔・段階数で、走路形状は元から代替実装です）。

### 適応の収束（再計測・解消）

以前は「レベルが固定点に収束せず振動する」「上限まで上がり続ける」状態でした。コース振幅の修正とセルフセンタリングにより、**同一の固定skillボットで収束するようになりました**（高負荷チャレンジON）。

| ミッション長 | 直近60秒の観測精度 | レベル範囲 |
|---|---|---|
| 3分 | **0.811 ± 0.013** | 40 – 54 |
| 10分 | **0.816 ± 0.001** | 51 – 67 |

いずれもデッドバンド77.5〜82.5%の内側で、レベルは有限の幅で安定します。3分でも収束するため、以前の「天井まで上昇」は解消しています。生データ: `docs/verification/convergence-3min.json`, `convergence-10min.json`。

**限界**: ボット計測であり人間の体感ではない。レベルは±7段階程度で動き続ける（精度を帯に保つための制御動作）。

### ナイトドライブを既定ON

「夜のほうが軽い」とのことでしたが、この環境（AMD RX 6400 / 1440×1000）で同一ミッションを昼夜比較したところ**差はほぼありませんでした**。60.0 FPS、CPUサブミット 2.37ms（昼）vs 2.42ms（夜）、ドローコールは両方402。vsyncで頭打ちなので差が出にくい可能性はあります。既定ONにはしました（好みとして）。

### ミッションの長さ（3分 / 10分 / 30分）

OTCとArcadeで選択可能にしました。イベントトラックと刺激スケジュールは長さに比例して生成されます。**Classicは公開仕様の180秒固定**（設定値を無視）。

### フィードバック文字の位置

画面中央に出ていた `KEEP YOUR LINE` / `AVOIDED` などを**左下**へ移動。ロードと標識の視界を塞ぎません。

### ガイドの取り方の説明

「はじめての方へ」に追記しました：7秒ほどで路面にリングが現れ、**リング内を走りながら標識の正解率とイベント通過を同時に満たす**と自動で溜まる。条件が欠けるとHUDに理由が出る。色の意味（ライム＝通る、赤白＝触れない）も明記。
